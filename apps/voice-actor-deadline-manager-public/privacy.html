プライバシーポリシー

最終更新日：2026年11月5日

1. アプリの概要と適用範囲

本アプリは、声優・アーティストの公式ニュースから公演日程や申込期限などを抽出し、利用者が設定したGoogle Calendarに同期するツールです。本ポリシーは、アプリによる情報の取得・利用・保存・送信を対象とします。実行環境、Googleおよびバックアップ先サービスの取り扱いには、それぞれの設定や規約も適用されます。

2. 取得する情報と利用目的

  • 公式ニュース：記事URL、タイトル、公開日、本文、アーティスト情報など。公演日程や受付日時の抽出、根拠の確認、更新検知に使用します。
  • Google Calendarの情報：設定先カレンダーの情報と、管理対象予定のID、件名、開始・終了日時、説明、場所、通知設定、状態、ETag、アプリ用の非公開拡張属性など。アクセス確認、予定の照合、外部編集との競合検知、同期に使用します。取得時にはAPIが返す予定オブジェクトを処理します。
  • OAuth認証情報：アクセストークン、リフレッシュトークン、有効期限、許可されたスコープなど。Calendar APIへの継続アクセスとトークン更新に使用します。
  • 処理・運用情報：抽出結果、出典、確認タスク、同期状態、操作ID、処理結果、再試行回数、API使用量など。抽出内容の確認、重複や競合の抑制、障害調査に使用します。

3. Google APIへのアクセス権限

Desktopアプリ用OAuth認証を使用し、利用者が同意して許可した権限でアクセスします。

実装で要求するOAuthスコープ
スコープ利用目的
https://www.googleapis.com/auth/calendar.events予定へのアクセス権限。管理対象予定の取得・作成・更新・削除に使用します。権限自体はアプリが作成した予定だけに限定されません。
https://www.googleapis.com/auth/calendar.readonlyカレンダーと予定の読み取り権限。設定されたカレンダーへのアクセス確認に使用します。権限自体はこの確認用途より広い範囲を含みます。

同期処理は予定IDとアプリ識別属性を照合します。Calendarへの書き込みは明示的に許可する設定が必要です。公演名・受付名、日時、会場、出典URL、通知設定、状態、同期用の識別属性などをGoogleに送信し、同期ルールに従って作成・更新・削除します。

Gemini APIは別途設定するAPIキーで使用します。調査範囲では、Gmail APIやGoogle Drive APIを直接呼び出す実装は確認されていません。

4. データの保存と保存期間

  • ローカルSQLite：記事本文・抽出結果・出典・確認履歴・カレンダーID・予定ID・同期予定データ・同期済みデータ・ETagなどを保存します。調査範囲ではDB全体を一定期間で自動削除する処理は確認できず、実際の保存期間は未確認です。
  • ローカルJSON：OAuthトークンと関連情報を保存します。トークンは自動更新されるため、有効期限の経過が保存ファイルの削除を意味するわけではありません。保存時の暗号化処理は確認できませんでした。
  • ログ：サービス専用ログには操作ID、処理結果、再試行回数などを記録します。日次ローテーションで当日分と過去13世代を保持し、古い日付のログを整理する実装があります。OSや配備先のログ保存期間は別途確認が必要です。
  • バックアップ：SQLite全体をローカルに複製し、日次7世代・週次4世代を保持する処理があります。転送処理を実行するとrcloneの設定先にも保存し、転送検証後に旧世代を整理します。実行されない期間や転送失敗時の残存を含め、厳密な削除期限を保証するものではありません。
  • Google Calendar：同期した予定はGoogle側に保存されます。アプリ停止やOAuth連携解除による自動削除は確認できませんでした。

任意の解析証跡出力インターフェースもありますが、実運用での有効化、出力先、保存期間は未確認です。バックアップ先のサービス名・所在・アクセス権、外部サービス側の保存期間も運用者による確認が必要です。

5. 外部サービスへの送信・第三者提供

  • Google Calendar / OAuth：認証・トークン更新と、予定の取得・作成・更新・削除のためにGoogleへ通信します。
  • Gemini API：ニュースのタイトル、公開日、アーティスト名、正規化本文を解析やトークン数の見積もりのために送信します。過去の解析結果を補助情報として送る機能もあります。調査した通常の解析経路では、Calendarから取得した予定やOAuthトークンをGeminiへ渡す処理は確認されていません。
  • rcloneの転送先：バックアップ転送時にはSQLite全体を送るため、DB内のCalendar同期情報も転送対象に含まれます。転送先サービスは設定に依存し、公開ソースからは特定できません。
  • 公式ニュースサイト：記事取得のためにアクセスします。アクセス先には通信に伴うIPアドレスなどが伝わります。

調査範囲では広告配信、データ販売、その他の第三者共有を行う処理は確認されていません。運用上の共有や、Geminiの料金プランに応じた入力の保持・学習利用条件、バックアップ事業者による取り扱いは未確認です。

6. 安全管理

OAuth認証にはPKCEとstate検証を使用します。トークン保存では、一時ファイルを所有者のみ読み書き可能な権限（POSIXの0600）で作成して置き換える処理があります。バックアップ・専用ログにもファイル権限の設定があり、配備例には専用実行ユーザーやディレクトリ権限の制限があります。Google APIとの通信にはHTTPSを使用します。

これらの権限の有効性はOSと実際の配備設定に依存します。トークン・DB・バックアップの保存時暗号化、転送先の設定、端末の保護が実施されているとは断定できません。

7. データの削除

調査範囲では、全データをまとめて消去する専用機能は確認されていません。利用を終了する場合は、実行中のアプリと定期実行・バックアップを停止したうえで、次の対象を個別に確認してください。

  1. Google Calendar上の対象予定を確認して削除する。ローカルDBを先に消すと同期先との対応情報も失われます。
  2. 実行環境に保存したOAuthトークン、不要になったクライアント認証情報・APIキー設定、SQLiteと関連ファイル、ログ、任意の解析証跡、ローカルのバックアップを削除する。
  3. rcloneの転送先のバックアップと、必要に応じてサービス側のごみ箱・履歴も確認する。外部サービスの保持や削除手順は提供元の仕様に従います。

記事や同期情報の論理的な廃止は、DB・バックアップ・Google上のデータを完全に消去することと同じではありません。実際のファイル名や保存先は利用者の設定で確認してください。

Googleアカウントとの連携解除

Googleアカウントのサードパーティとの接続管理で本アプリに対応する接続を選び、アクセス権を取り消せます。連携解除だけでは、ローカルのトークンファイル、保存済みデータ、バックアップ、作成済み予定は削除されません。再取得を防ぐには定期実行の停止と保存データの削除も必要です。

8. Google API Services User Data Policy

Googleユーザーデータの利用には、Google API Services User Data Policyと、該当するLimited Use要件への対応が必要です。確認できたCalendarデータの用途は、予定同期・状態照合とその運用情報の保存です。

バックアップ転送の必要性と利用者の同意、データへの人のアクセス、第三者の利用条件、広告や汎用AIモデルの学習への利用がないことなどを、実運用と契約の両面で確認する必要があります。

9. ポリシーの変更

本ポリシーの修正時には、このページの内容と最終更新日を更新します。新しいデータ利用目的を追加する場合の通知・再同意方法は、運用者が決定する必要があります。
