1. アプリの概要と適用範囲

本アプリは、声優・アーティストの公式ニュースから公演日程や申込期限などを抽出し、利用者が設定したGoogle Calendarに同期するツールです。本ポリシーは、アプリによる情報の取得・利用・保存・送信を対象とします。実行環境、Googleおよびバックアップ先サービスの取り扱いには、それぞれの設定や規約も適用されます。

2. 取得する情報と利用目的

  • 公式ニュース：記事URL、タイトル、公開日、本文、アーティスト情報など。公演日程や受付日時の抽出、根拠の確認、更新検知に使用します。
  • Google Calendarの情報：設定先カレンダーの情報と、管理対象予定のID、件名、開始・終了日時、説明、場所、通知設定、状態、ETag、アプリ用の非公開拡張属性など。アクセス確認、予定の照合、外部編集との競合検知、同期に使用します。取得時にはAPIが返す予定オブジェクトを処理します。
  • OAuth認証情報：アクセストークン、リフレッシュトークン、有効期限、許可されたスコープなど。Calendar APIへの継続アクセスとトークン更新に使用します。
  • 処理・運用情報：抽出結果、出典、確認タスク、同期状態、操作ID、処理結果、再試行回数、API使用量など。抽出内容の確認、重複や競合の抑制、障害調査に使用します。

3. Google APIへのアクセス権限

Desktopアプリ用OAuth認証を使用し、利用者が同意して許可した権限でアクセスします。

実装で要求するOAuthスコープ
スコープ利用目的
https://www.googleapis.com/auth/calendar.events予定へのアクセス権限。管理対象予定の取得・作成・更新・削除に使用します。権限自体はアプリが作成した予定だけに限定されません。
https://www.googleapis.com/auth/calendar.readonlyカレンダーと予定の読み取り権限。設定されたカレンダーへのアクセス確認に使用します。権限自体はこの確認用途より広い範囲を含みます。

同期処理は予定IDとアプリ識別属性を照合します。Calendarへの書き込みは明示的に許可する設定が必要です。公演名・受付名、日時、会場、出典URL、通知設定、状態、同期用の識別属性などをGoogleに送信し、同期ルールに従って作成・更新・削除します。

Gemini APIは別途設定するAPIキーで使用します。調査範囲では、Gmail APIやGoogle Drive APIを直接呼び出す実装は確認されていません。

4. データの保存と保存期間

  • ローカルSQLite：記事本文・抽出結果・出典・確認履歴・カレンダーID・予定ID・同期予定データ・同期済みデータ・ETagなどを実行環境のDBに保存します。保存期間は運用者の設定・削除作業に依存し、一定日数での自動削除は保証されません。
  • ローカルJSON：OAuthトークンと関連情報を実行環境のファイルに保存し、必要に応じて更新します。有効期限の経過や連携解除だけではファイルは削除されません。トークンの保存処理自体は暗号化を行わないため、保存先の保護が必要です。
  • ログ：サービス専用ログには操作ID、処理結果、再試行回数などを記録します。専用ログを有効にした場合、日次ローテーションで当日分と過去13世代を保持し、ログの初期化時やローテーション時に古い日付のログを整理します。アプリ停止中の削除は行われず、OSや配備先が別途保存するログの保持期間は、それらの設定に従います。
  • バックアップ：バックアップ処理を実行するとSQLite全体をローカルに複製し、日次7世代・週次4世代を保持します。転送処理を実行するとrcloneの設定先にも保存し、転送検証後に日次7世代・週次4世代を超える旧世代を整理します。処理が実行されない期間や転送失敗時にはデータが残るため、世代数は厳密な削除期限を保証するものではありません。
  • Google Calendar：同期した予定はGoogle側に保存されます。アプリ停止やOAuth連携解除だけでは削除されません。

試行実行で解析証跡の出力を有効にすると、記事本文を含む解析入力、Gemini APIへのリクエスト・応答などもローカルに保存します。CSV出力機能を使用すると、予定の件名・日時・説明などの同期情報もファイルに保存します。これらの出力先と保存期間は運用者が管理し、不要になったファイルを削除してください。バックアップ先のサービス・保存場所・アクセス権と、外部サービス側の保持期間は、選択したサービスの設定・契約に従います。

5. 外部サービスへの送信・第三者提供

  • Google Calendar / OAuth：認証・トークン更新と、予定の取得・作成・更新・削除のためにGoogleへ通信します。Calendarから取得した情報は、同期対象の照合、競合検知、同期状態の管理に使用します。
  • Gemini API：ニュースのタイトル、公開日、アーティスト名、正規化本文を解析やトークン数の見積もりのために送信します。過去の解析結果を補助情報として送る機能もあります。通常のニュース解析処理では、Calendarから取得した予定やOAuthトークンをGeminiへの入力に含めません。
  • rcloneの転送先：バックアップ転送を設定・実行した場合、SQLite全体の複製を送信します。記事本文や抽出結果に加え、DB内のカレンダーID・予定ID・同期予定データ・同期済みデータ・ETagなどのCalendar同期情報も含まれます。この転送処理は、別ファイルに保存するOAuthトークンや専用ログを対象にしていません。転送先は運用者がrcloneで選択したサービスです。
  • 公式ニュースサイト：記事取得のためにアクセスします。アクセス先には通信に伴うIPアドレスなどが伝わります。

外部サービス側での保持・利用条件は、利用するGemini APIの料金プランやバックアップ先の設定・契約により異なります。利用前に、入力データの保持・学習利用条件と、バックアップ先でのデータの取り扱いを確認してください。本ページで説明するデータ利用・送信の目的に、広告配信やデータ販売は含みません。

6. 安全管理

OAuth認証にはPKCEとstate検証を使用します。トークン保存では、一時ファイルを所有者のみ読み書き可能な権限（POSIXの0600）で作成して置き換える処理があります。バックアップ・専用ログにもファイル権限の設定があり、配備例には専用実行ユーザーやディレクトリ権限の制限があります。Google APIとの通信にはHTTPSを使用します。

これらの権限の有効性はOSと実際の配備設定に依存します。保存時の暗号化、バックアップ転送先の保護、端末の保護は実行環境側で設定・管理する必要があり、アプリの導入だけで保証されるものではありません。

7. データの削除

利用を終了する場合は、実行中のアプリと定期実行・バックアップを停止したうえで、次の対象を個別に削除してください。

  1. Google Calendar上の予定：Google Calendarで対象予定を確認して削除します。通常の同期でも同期ルールに従って管理対象予定を削除しますが、利用終了時の一括消去とは異なります。ローカルDBを先に消すと同期先との対応情報も失われます。
  2. OAuth認証情報：Googleアカウントでアクセス権を取り消し、実行環境のトークンファイルと不要になったクライアント認証情報・APIキー設定を削除します。ファイルを削除するだけでは、Google側のアクセス権は取り消されません。
  3. ローカルデータ：SQLiteと関連ファイル、ログ、解析証跡やCSV出力、ローカルのバックアップを削除します。実際のファイル名や保存先は利用者の設定で確認してください。
  4. 転送済みバックアップ：rcloneの転送先でも別途削除し、必要に応じてサービス側のごみ箱・履歴も確認してください。外部サービスの保持や削除手順は提供元の仕様に従います。

記事や同期情報の論理的な廃止は、DB・バックアップ・Google上のデータを完全に消去することと同じではありません。

Googleアカウントとの連携解除

Googleアカウントのサードパーティとの接続管理で本アプリに対応する接続を選び、アクセス権を取り消せます。連携解除だけでは、ローカルのトークンファイル、保存済みデータ、バックアップ、作成済み予定は削除されません。再取得を防ぐには定期実行の停止と保存データの削除も必要です。

8. Google API Services User Data Policy

Googleユーザーデータの利用には、Google API Services User Data Policyと、該当するLimited Use要件が適用されます。本アプリでのCalendarデータの用途は、予定同期・状態照合と、そのための運用情報の保存・バックアップです。送信先と対象データは「外部サービスへの送信・第三者提供」に記載しています。

Calendarデータを含むバックアップを転送する場合は、利用者に送信先・対象データ・目的を説明し、同意を得た範囲で行う必要があります。運用者は、人によるデータへのアクセスを要件上認められる範囲に制限し、転送先の契約・設定でも用途が制限されることを確認してください。広告目的の利用・販売や汎用AIモデルの学習にGoogleユーザーデータを利用する運用は、本ポリシーが説明する利用範囲に含みません。

9. ポリシーの変更

本ポリシーの修正時には、このページの内容と最終更新日を更新します。Googleユーザーデータを新しい方法や目的で利用する場合は、利用を開始する前に変更内容を利用者へ説明し、同意を得る必要があります。
